Fix `Layout.get_primitives` / `Layout.filter_primitives` on the gRPC backend in two scenarios:

* Filtering on non-stackup layers (for example `Outline`, `Measures`, `Comment`) returned an empty list because the cached `primitives_by_layer` mapping is initialized only with stackup-layer keys. The optimization is now used only when every requested layer is a stackup layer; otherwise the call falls back to iterating all primitives, matching the dotnet backend behavior.
* Primitives whose underlying gRPC objects are in an inconsistent state on the server (raising `RuntimeError: Illegal operation on a null Layer object` and similar) used to abort the whole filter call. They are now silently skipped so the remaining valid primitives are still returned.
